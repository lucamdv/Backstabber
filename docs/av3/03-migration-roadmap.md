## Pontos de verificação entre implementações

- **Fixtures de contrato.** Capturar o JSON autorizado por identidade após cada comando. Comparar campos, valores, ordem de listas, omissão versus `null`, UTC, códigos e status. Para fingerprints, reproduzir a serialização do envelope normalizado, inclusive a omissão de `targetId` ausente e a ordem de `keepIds`. Cobrir versões anteriores de estado JSONB usadas no ambiente de homologação.
- **Concorrência observável.** Usar duas conexões independentes e comprovar espera no PostgreSQL, como faz `native-postgres.test.ts`. Amizades bloqueiam perfis em ordem de UUID. Convites bloqueiam a sala antes da escrita. Operações mutáveis de partida bloqueiam sala e depois partida. Confirmar que retry com mesmo ID após timeout, deadlock ou falha de rede no commit não duplica efeitos.
- **Segurança das sessões.** Derivar autor do UUID validado pelo Supabase. Exercitar permissões com credenciais de cliente e de serviço isoladas. Projetar a resposta a partir do participante autenticado e verificar os JSONs também após encerramento, reconexão e revanche. Usar a migração existente apenas em PostgreSQL de desenvolvimento ou teste.
- **Homologação sem troca de produção.** Rodar E2E com duas origens da API e o mesmo contrato React. Incluir perfis novos, convite, última vaga, host ausente, prontidão, quatro participantes na reação, interrupção de conexão, perda privada e revanche. Executar comparação de banco e Realtime com sessões autorizadas antes de propor publicação. O Node.js continua como backend oficial durante a migração.
