# Auth interface review captures

Generated by `web/e2e/auth-terminal.spec.ts` in local Chrome. The test explicitly replaces `auth.ts` with a browser fixture. These images demonstrate interface behavior; they do not demonstrate a real Google login, Supabase authentication, or delivery of an email.

All account examples are fictitious. Password fields are empty in every capture. `000000` is a static example, not an authentication token.

Exception: `hosted-staging-profile.jpg` is a real Chrome capture from the Java staging Preview after Google login and password recovery. It shows a deliberately synthetic test profile, without email, Auth UUID, credentials, codes or session data. It is evidence of the rendered profile, not proof of every authentication network step.

On narrow screens the online surface scrolls normally. `*-viewport-390x844.png` captures the original viewport at its initial scroll position; `*-keyboard-bottom-390x844.png` shows the original viewport after navigating to the final control with Tab. The login/signup `*-390x844.png` images use `fullPage: true` and a temporary screenshot-only expansion of the fixed scroll surface so reviewers can see all controls together. This expansion does not modify product code or the viewport used for geometry and keyboard checks.

Other terminal captures use the named viewport. Email images capture the complete static HTML previews at 390 and 1366 pixels wide. Their code and links are inert examples.
